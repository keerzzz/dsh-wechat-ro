# 多系统微信历史：平台支持与适配

产品目标是将 **Windows、macOS、Linux 桌面微信** 的本人历史接入同一个 DSH 工作区，提供统一的搜索、原文引用、自动更新和每日数据卡片。

## 分开记录三个事实

| 维度 | 需要记录的内容 | 原因 |
| --- | --- | --- |
| DSH 宿主系统 | Windows / macOS / Linux、运行时版本、文件路径 | 决定进程、权限、文件访问和路径处理方式 |
| 历史来源 | 微信系统、客户端版本与构建、账号范围 | 决定历史位置、取钥方式及采集实现 |
| 数据格式 | 数据库布局、表字段、压缩格式、时间和副本代次 | 决定查询与卡片能否正确解析 |

不同系统产生的历史可以进入相同的业务流程；采集后的副本是否兼容，仍由实际格式核验。微信网络连接成功也不能单独证明本机历史读取已适配。

## 可追溯的实现差距

- [历史准备助手](../scripts/prepare_local_history.py) 使用 `/proc`、`fcntl`、`pkexec` 和 Linux 进程身份。
- [运行时取钥](../vendor/wcdb_runtime_keys.py) 固定当前已核验的 Linux 微信构建。
- [原生查询 worker](../plugin/lib/archive-query-worker.js) 拒绝 `process.platform !== 'linux'` 的宿主，并通过 `/proc/self/fd` 固定目录和数据库文件。
- [任务路径处理](../plugin/lib/task-access.js) 与原生会话边界需要补齐 Windows 盘符、分隔符及平台文件身份处理。
- [Python MCP 查询](../wechat_ro_mcp/db.py) 已采用 `pathlib` 和 SQLite 文件 URI；这提供复用基础，当前尚无 Windows/macOS 环境通过工件。

## 实施顺序与验收

1. 按各系统的实际微信版本和样本核对目录、数据库布局、压缩和时间，形成合成回归夹具。
2. 在现有入口补齐 Windows/macOS 的路径和已解密副本查询，验证原文、分页、引用、北京时间及数据卡片。
3. 分别实现平台采集、账号与构建核验、副本生成和刷新；验证失败保留旧副本以及同轮分页固定代次。
4. 在各平台验证一键导入、搜索前更新、分钟检查、定时卡片和本人手机回复。

平台实现采用现有入口和协议。当前只有一个可运行的采集/原生 worker 平台，先落地并验证第二个实现，再归并已经出现的重复代码。第二个平台完成前，跨平台采集与文件访问仍是工程待办。

CI 当前在 Ubuntu 运行一个 plugin 包的串行门禁。新增平台实现后，在相应系统运行同一包的适用门禁并串行验收；Ubuntu 通过记录仅覆盖实际执行的环境。现有 CI 和本机回归记录见 [代码质量说明](code-quality.md)。
